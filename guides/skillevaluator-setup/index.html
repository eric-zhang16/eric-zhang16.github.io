SkillEvaluator Setup Guide

Install NVIDIA's SkillEvaluator, scan and validate a skill, and run its live agent evaluation — with a look at what Claude Code and NVIDIA's hosted LLM each actually do when a "Claude Code" trial runs on a non‑Anthropic key.

How the evaluation works

Three tiers run in sequence. Only the last one needs a live agent and a model behind it — the first two are static checks and embedding similarity.

Part 1 native Windows

Tiers 1 and 2 need no Linux layer — they ran fine directly on Windows once the scanners were on PATH.

  1. Install uv

    py -m pip install --user uv

    Your system Python can be newer than SkillEvaluator's declared support (3.12–3.14) — that's fine, uv provisions its own pinned interpreter per command.

  2. Clone the repo

    git clone --depth 1 https://github.com/NVIDIA/SkillEvaluator.git
cd SkillEvaluator

  3. First run bootstraps everything

    py -m uv run --python 3.13 skillevaluator --help

    Pin --python 3.13 explicitly — it's the version this release targets.

  4. Install the Tier 1 scanners

    # SkillSpector (security)
py -m uv tool install --python 3.13 ^
  https://github.com/NVIDIA/SkillSpector/releases/download/v2.13.3/skillspector-2.13.3-py3-none-any.whl

# Gitleaks (secrets) — no installer, just the release binary
curl -sL -o gitleaks.zip ^
  https://github.com/gitleaks/gitleaks/releases/download/v8.30.1/gitleaks_8.30.1_windows_x64.zip
# unzip gitleaks.exe into the same folder uv used, e.g. %USERPROFILE%\.local\bin

    Pin --python 3.13 here too: SkillSpector's yara-python dependency ships no prebuilt wheel for newer Pythons on Windows, so the default interpreter fails to build it from source.

  5. Put the tools on PATH

    $env:PATH = "$env:USERPROFILE\.local\bin;$env:PATH"

    Every new shell needs this — uv tool install warns about it but doesn't fix it for you.

  6. Run Tier 1

    py -m uv run --python 3.13 skillevaluator validate "<path-to-skill>" -r cli

    Exit 0 and "9/9 checks passed" means schema, security, PII, license, and quality all cleared.

  7. Get a free NVIDIA Build key

    build.nvidia.com → sign in → open any model page → Get API Key. One key covers every model.

  8. Run Tier 2

    $env:SKILL_EVAL_LLM_PROVIDER = "nv_build"
$env:NVIDIA_API_KEY = "nvapi-..."
py -m uv run --python 3.13 --extra tier2 skillevaluator tier2 "<path-to-skill>"

    Chunks the skill's files, embeds them, and clusters for repeated/overlapping guidance — embeddings only, no live agent.

Part 2 WSL2

Tier 3's local live-agent mode is Linux-only. On Windows, doctor fails outright with "Native Windows local mode is unsupported."

  1. Install WSL2 — from an elevated shell

    # PowerShell, Run as Administrator
wsl --install

    Reboot when it asks. If wsl -l -v still shows no distro afterward, the platform installed but Ubuntu didn't — run wsl --install -d Ubuntu next.

  2. Create the Ubuntu user — interactively, in a real window

    Open the Ubuntu app from the Start menu yourself and finish the Enter new UNIX username / password prompts there.

    Running the install from a script or non-interactive shell leaves it stuck at "Waiting for OOBE command to complete" forever — the first-boot prompt has no keyboard to read from.

  3. Install uv inside WSL — no sudo

    curl -LsSf https://astral.sh/uv/install.sh | sh

  4. Clone the repo again, inside WSL

    mkdir -p ~/claude && cd ~/claude
git clone --depth 1 https://github.com/NVIDIA/SkillEvaluator.git

    WSL's filesystem is separate from Windows' — the Windows checkout isn't reachable the way uv run needs it.

  5. Install Node.js and the Claude Code CLI — no sudo

    curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
source ~/.bashrc
nvm install --lts
npm install -g @anthropic-ai/claude-code

    Ubuntu's default .bashrc returns immediately for non-interactive shells, before it reaches the lines that load nvm. Any scripted call needs source "$HOME/.nvm/nvm.sh" explicitly — don't rely on .bashrc having run.

  6. Install the tier3 extra and check readiness

    cd ~/claude/SkillEvaluator
export SKILL_EVAL_LLM_PROVIDER=nv_build
export NVIDIA_API_KEY="nvapi-..."
uv run --python 3.13 --extra tier3 skillevaluator doctor \
  --env-mode local --agents claude-code

    Every row should read pass — provider, credential, agent, and local prerequisite.

  7. Pick a model your key can actually call

    curl -s -H "Authorization: Bearer $NVIDIA_API_KEY" \
  https://integrate.api.nvidia.com/v1/models

    The provider's advertised default can be listed in the catalog yet still 404 on an actual chat request for a given key — catalog visibility isn't proof of working access. Confirm with a real call before trusting the default: uv run --python 3.13 --extra tier3 skillevaluator doctor --tier 2 --verify-models (look at the Deduplication model row).

  8. Set the model, exactly as the catalog spells it

    export SKILL_EVAL_LLM_MODEL="mistralai/mistral-large-4-1t-a52b"

    Only NVIDIA's own entries carry an nvidia/ prefix in the catalog ID. Every other publisher's models use their own namespace as-is (mistralai/…, deepseek-ai/…, ai21labs/…) — adding nvidia/ in front of those produces a model string the endpoint doesn't recognize.

  9. Run Tier 3

    uv run --python 3.13 --extra tier3 skillevaluator tier3 \
  "<path-to-skill>" --agents claude-code --env-mode local \
  --agent-model claude-code=mistralai/mistral-large-4-1t-a52b

    Local mode runs the agent directly on the WSL host rather than in a container — fine for your own trusted skills, not for third-party ones (use --env-mode docker there instead).

Gotchas worth knowing

PATH resets

Both .local/bin (Windows) and the scanner binaries need re-adding to PATH in every fresh shell — SkillEvaluator doesn't persist it for you.

model naming

Don't prepend nvidia/ to a non-NVIDIA catalog ID. Copy the ID exactly as /v1/models returns it.

catalog ≠ access

A model showing up in the catalog listing doesn't mean your key can call it — verify with doctor --verify-models, which sends a real request, before spending a full Tier 3 run finding out.

free-tier limits

NVIDIA Build's free key is commonly reported around 30–40 requests/minute, account-wide across every model, and scoped to dev/test use rather than production.

local mode is experimental

NVIDIA's own docs flag it as intended for trusted skills and workspaces — reach for Docker instead when evaluating anything you didn't write yourself.
